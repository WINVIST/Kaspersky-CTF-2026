# Sudokrypt

**Категория:** Crypto  
**Стоимость:** 72

> Stacy asked for my help with her homework...

Сервис давал 96 запросов на шифрование одного 16-байтового блока и один раз позволял получить зашифрованный флаг:

```text
nc tcp.sasc.tf 31415
```

В архиве лежали `server.py` и `sudokrypt_core.py`. Сам шифр выглядел громоздко: Hexadoku-перестановки, несколько обратимых преобразований 16-битных слов и отдельный «спектральный» генератор для каждого из 16 байтов блока.

## Разбор

Сначала я посмотрел на конец `crypt_block`:

```python
values = self.prng.next_block()
words = [self.inner_word(byte, values[i]) for i, byte in enumerate(plaintext)]

rotation = block_rotation(values, block_number)
ranked = [words[(rank + rotation) & 15] for rank in range(16)]
wrapped = [public_wrapper(word, rank) for rank, word in enumerate(ranked)]
mixed = diffuse_words(wrapped)
```

Два последних слоя не используют секретный ключ и полностью обратимы. Функция `unpack_rank_words` из исходников сразу снимает `diffuse_words` и `public_wrapper`. После этого остаются 16 внутренних слов, только циклически сдвинутых на неизвестный `rotation`.

Внутри каждого слова лежат четыре полубайта:

```text
q_label | row_field | col_field | check_field
```

Они зависят от байта открытого текста, скрытых перестановок `q_perm` и `symbol_perm`, а также от значения потока в диапазоне `0..4092`.

### Восстановление перестановок

Лимит запросов я разделил на три части.

Первые 16 блоков состояли из одинакового байта:

```python
byte = (q << 4) | q
plaintext = bytes([byte]) * 16
```

Здесь во всех позициях `symbol = 0`, а старший полубайт внутреннего слова напрямую даёт `q_perm[q]`. По одному запросу на каждый `q` хватает, чтобы восстановить всю перестановку `q_perm`.

Дальше я использовал блоки, в которых номер канала совпадает с `q`:

```python
bytes((q << 4) | ((symbol + q) & 0xf) for q in range(16))
```

После восстановления `q_perm` по каждому слову уже известен исходный канал. Поэтому циклический сдвиг находится прямо из позиции слова:

```text
rotation = q - rank mod 16
```

Для каждого символа я отправлял два таких блока. Затем перебирал 16 вариантов `symbol_inv[symbol]` и все 4093 возможных значения потока. Поля `row`, `col` и `check` оставляли мало кандидатов, а пересечение двух наблюдений вместе с условием, что `symbol_inv` является перестановкой, снимало неоднозначность.

Сначала я пытался использовать только одинаковые блоки. Это не сработало: для некоторых символов оставалось сразу несколько подходящих перестановок и циклических сдвигов. Привязка `q` к номеру канала как раз решила эту проблему.

### Спектральный генератор

Основная слабость была в `SpectrumGenerator`. Для канала `l` значение блока `n` имеет вид:

```text
V_l(n) = Σ c[l][j] * nodes[j]^n mod 4093,   j = 0..55
```

То есть каждый канал является линейной рекуррентной последовательностью порядка 56. Характеристический многочлен

```text
P(x) = ∏ (x - nodes[j])
```

одинаков для всех 16 каналов.

После 16 запросов на `q_perm` у меня оставалось 80 последовательных точных значений на каждый канал: 32 блока для восстановления символов и ещё 48 блоков с `symbol = 0`.

Для одного канала 80 значений маловато, но каналов 16 и рекурсия у них общая. Я составил уравнения

```text
V_l(n+56) + a55*V_l(n+55) + ... + a0*V_l(n) = 0 mod 4093
```

для всех каналов. Получилось `16 * (80 - 56) = 384` уравнения на 56 коэффициентов. Обычным методом Гаусса по модулю 4093 восстановил характеристический многочлен.

Поле маленькое, поэтому корни не пришлось факторизовать: я просто проверил все числа от 1 до 4092 и получил ровно 56 узлов `nodes`.

После этого для каждого канала решил систему Вандермонда и восстановил коэффициенты `c[l][j]`. Наблюдения начинались с блока 16, поэтому в конце компенсировал сдвиг:

```text
c[l][j] = shifted_c[l][j] / nodes[j]^16 mod 4093
```

### Fold и расшифровка флага

Перед шифрованием флага сервис вызывает `fold_for_flag` и домножает каждую спектральную компоненту на дополнительную степень узла:

```python
shift = 1 + (
    coefficients[lane][j] * (lane + 1) + (j + 3) * (j + 7)
) % (FIELD - 1)
```

Простой прогноз рекурсии здесь не помог бы, потому что `shift` зависит от секретных коэффициентов. Но после восстановления точных `nodes` и `coefficients` я смог полностью повторить fold локально, сгенерировать поток для блоков флага и обратить оставшиеся слои шифра.

Полный эксплойт лежит в [solve.py](solve.py). Рядом сохранён оригинальный [sudokrypt_core.py](sudokrypt_core.py), который нужен для запуска:

```bash
python3 solve.py
```
